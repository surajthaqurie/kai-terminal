### 0.2 Open by design or OS limit (not fixable)

- **Windows 7/8/8.1** are unsupported: no native ConPTY API (§1.1).
- **Canonical line mode:** the OS kernel's 4,096-byte canonical line limit still applies to line-buffered input (§1.2).
- **8 panes per tab** and the 1/8 minimum-size floor are intentional (§1.3).
- **OS-reserved global hotkeys** (e.g. `Cmd+Space`) cannot be overridden by webview shortcuts (§1.4).
- **Local-only persistence:** workspaces, settings and indexes stay on the machine; no sync or telemetry (§1.5, §1.8, §2).
- **Auth is not verified over the network:** only local config-file presence is checked, to avoid costs (§1.6).
- **`git` binary required** for the status badge; missing git only disables the badge (§1.7).
- **No language server installed:** deep type inference falls back to deterministic pattern parsing (§1.8).
- **In-app update from v0.1.7 and v0.2.0 fails:** those builds reject their own downloaded installer with "Update installer not found" (fixed in the next release; an installed binary cannot be patched). Install the next release manually from the releases page once; in-app updates work from then on.
- **Detached grandchild processes** (double-fork, `setsid`, Windows detached) cannot be reaped from Node; outcomes are reported as point-in-time (§5.1, §5.6).
- **Edits preserving size, mtime and ctime** on a file hashed more than 5 s after its last change can evade freshness detection until the next full rebuild (§5.2).
- **Flatpak shells run inside the sandbox:** Kai starts its shell directly, so a Flatpak install gets the sandbox's shell and tools, not the host's (`--filesystem=host` only exposes files). Use the `.deb`, `.AppImage` or snap for a host shell.
- **WSL has no hosted CI runner:** verification is manual-only (§4.2).
- **Call detection recognises known call apps only:** Music Time pauses while Teams, Zoom, Skype, Webex, Slack, Discord, WhatsApp, Telegram, Signal, Phone Link and similar apps (and browsers, for Meet / web Teams) record from the microphone. Dictation, recorders and other mic users do not pause it, but a call app missing from the list, a listen-only call, and browser voice-typing are not told apart. macOS cannot attribute the microphone to an app, so there it needs a native call app open and does not see browser calls. This is automatic whenever the player is playing (no setting): music pauses for the call and resumes when it ends; music paused before the call stays paused. Linux needs `pactl` (PulseAudio or PipeWire-pulse).
- **Pure-MCP clients** must follow writes with a graph read or `kai_sync_graph`, unless the opt-in `--watch` watcher is on (§5.4).

## 1. Operating System & Platform Boundaries & Resolutions

### 1.1 Windows ConPTY Semantics
- **Implementation Change:** Added an explicit Windows version gate (`MIN_SUPPORTED_WINDOWS_BUILD = 17763`, Windows 10 v1809 / Windows 11) in `shell.rs` (`check_host_pty_support()`). Unsupported builds return a typed `TerminalError::PtyCreationFailed` with actionable upgrade instructions. Added WSL detection (`is_wsl_shell_path`) that appends service diagnostic hints (`wsl_failure_hint()`) for WSL startup errors. Reaped process cleanup on window/application close preventing orphan processes.
- **Tests Added:** `test_windows_build_gate_accepts_supported_builds`, `test_windows_build_gate_rejects_legacy_builds_with_actionable_error`, `test_wsl_shell_path_detection`.
- **Actual Test Result:** Passed (38/38 Rust unit tests, 13/13 real PTY integration tests).
- **Platform Coverage:** Windows 10 (build >=17763), Windows 11, WSL (Linux sub-environment).
- **Remaining Limitation:** Windows 7/8/8.1 are intentionally unsupported due to missing native ConPTY API support.

### 1.2 Unix PTY Input & Output Reliability
- **Implementation Change:** Implemented byte-exact streaming (`write_bytes_chunked`) in 32 KiB chunks over native PTY master writer with `ErrorKind::Interrupted` retry and partial write looping. Enforced a 1 MB input payload cap per write call (`MAX_INPUT_WRITE_BYTES`) returning an explicit error prompt instead of freezing. Output is read in 4 KiB chunks, UTF-8 validated preserving trailing multi-byte sequences (`split_valid_utf8`), emitted via IPC, and rendered on frontend with `requestAnimationFrame` batching.
- **Tests Added:** `test_write_chunked_preserves_exact_bytes`, `test_oversized_input_rejected_not_truncated`, `test_large_multiline_unicode_paste_delivered`, `test_04_ansi_colors_and_unicode`, `test_08_high_volume_output_and_memory`.
- **Actual Test Result:** Passed.
- **Platform Coverage:** Linux, macOS, Windows (ConPTY).
- **Remaining Limitation:** OS kernel canonical line mode still applies to line-buffered input; interactive shells requiring long uncommitted lines must switch to raw mode (standard Unix behavior).

### 1.3 Split Panes & Input Isolation
- **Implementation Change:** Implemented multi-pane tab architecture (up to 8 independent PTY sessions per tab, horizontal and vertical splits; `MAX_PANES_PER_TAB` in `paneLayout.ts` is the single source of truth, also used by workspace persistence and restore) in `paneLayout.ts` and `TerminalView.tsx`. Each pane maintains its own backend session UUID. Focus tracking routes keyboard input strictly to the active pane. Added drag-to-resize pane dividers and active-pane styling. Pane exit cleans up backend child processes. A size floor (`MIN_SPLIT_EXTENT`, 1/8 of the pane area per axis) refuses any split that would leave a pane narrower or shorter than that, so repeated splitting of one pane cannot produce unusably tiny terminals.
- **Tests Added:** `src/__tests__/paneLayout.test.ts`, `src/__tests__/terminal_pty_hardening.test.ts` (8-pane ceiling, balanced 4x2 grid, size floor), `src/__tests__/workspaceRestore.test.ts` (8-pane persistence + truncation), `test_10_multiple_simultaneous_sessions`, `test_11_child_process_cleanup`.
- **Actual Test Result:** Passed (37/37 Vitest tests, 13/13 integration tests).
- **Platform Coverage:** Cross-platform (Linux, macOS, Windows).
- **Remaining Limitation:** Pane count is capped at 8 per tab (and splits below the 1/8 size floor are refused) to preserve terminal rendering performance and readability. These limits are intentional.

### 1.4 Configurable Keyboard Shortcuts
- **Implementation Change:** Built centralized shortcut registry (`shortcuts.ts`) with configurable keybindings (`KeybindingsConfig`), conflict detection (`findConflicts`), modifier label translation (Cmd on macOS vs Ctrl on Windows/Linux), and settings UI (`SettingsModal.tsx`). Added shortcut actions for tab/pane navigation (`nextTab`, `prevTab`, `nextPane`), split pane, restart, search, command palette. Keystrokes are ignored when focused in text inputs (`isTypingTarget`).
- **Tests Added:** `src/__tests__/shortcuts.test.ts`.
- **Actual Test Result:** Passed.
- **Platform Coverage:** Cross-platform (macOS, Linux, Windows).
- **Fixed shortcuts:** copy/paste (`Ctrl+Shift+C/V`, `Ctrl/Shift+Insert`), `Ctrl+Shift+A/K/Home/End`, `Ctrl+=/-/0` zoom and `Ctrl+1-9` tab jump are not remappable. Plain `Ctrl+C` / `Ctrl+V` still reach the shell.
- **Remaining Limitation:** System-level OS global hotkeys reserved by host operating system (e.g. `Cmd+Space` on macOS) cannot be overridden by webview shortcuts. `Ctrl+-` / `Ctrl+_` (the readline "undo" byte) is claimed by zoom-out; use `Ctrl+x Ctrl+u` instead.

### 1.5 Named Sessions & Project Workspaces
- **Implementation Change:** Built versioned local workspace schema (`kai_workspaces_v1` v2) with migration from legacy formats (`terminal_workspaces_v1`, `terminal_tab_layout_v1` → "Restored session") in `workspaces.ts`. Added `WorkspaceModal.tsx` for creating, renaming, deleting, saving, and restoring named workspaces. Saving persists titles + cwd/shell + pane structure + nested split tree only (layout included via `nodeToPersistedLayout`); keystrokes, history, scrollback, env values, and secrets are strictly excluded and sanitized away on load. Restoration re-validates every tab (`sanitizeWorkspaceForRestore`: drops malformed tabs, clears un-restorable cwd values so the backend falls back to HOME) and mints fresh pane ids so no backend PTY session is ever reused. Invalid persisted layouts (stale ids, duplicate pane refs) fall back to an even tiling via `resolveTabLayout` (requires exact + unique cover) so every live pane renders exactly once. Added working directory path validation (`validateWorkspaceDir`; existence checked at launch by the backend) and environment variable override support in project settings (`ProjectWorkspaceSettings`).
- **Tests Added:** `src/__tests__/workspaces.test.ts`, `src/__tests__/workspaceRestore.test.ts` (corrupted new-key recovery, migration preserved, no-secret persistence, restore-time path validation, duplicate-ref repair, settings recovery, conflict + platform-modifier preservation), `test_validate_and_resolve_cwd_valid_and_invalid`.
- **Actual Test Result:** Passed.
- **Platform Coverage:** Cross-platform.
- **Remaining Limitation:** Saved workspaces persist layout metadata locally in `localStorage`; no remote sync or network transfer is included by design.

### 1.6 AI CLI Diagnostics & Provider Integration
- **Implementation Change:** Created provider-neutral diagnostic state enum (`AiCliDiagnosticState`: `not_found`, `version_detected`, `probe_failed`, `authentication_required`, `authentication_failed`, `ready`, `launch_failed`, `unsupported_version`, `unknown`). Five signals stay separate by construction: executable discovery (PATH lookup), version detection (bounded `--version`), local config-file presence (`auth_status`: `config_present` / `config_missing` / `unknown` — existence only, never credential validity), authentication verification (no passive check performs it; only an explicit user launch can prove sign-in, so passive probing never reports `ready`), and launch validation (custom paths). A version response never implies authentication, and config-file presence never proves credentials are valid. Auto-detects 10 catalogued agents (`codex`, `claude`, `gemini`, `opencode`, `copilot`, `aider`, `cursor`, `windsurf`, `cline`, `agy`) with passive, local, non-billable checks only (no network, no paid calls, no credential writes). Probes `--version` directly (no shell) with a strict 5-second timeout and kill+reap on expiry so no probe lingers (`probe_version`); output is truncated to the first line / 512 chars and never logged with secrets. Config presence checks test existence only — file contents (tokens/secrets) are never read or logged. Version gating is implemented end to end (`parse_version_triple`, `classify_version`, `MIN_SUPPORTED_VERSIONS`): a probed `--version` line is parsed tolerantly (`codex-cli 0.46.0`, `2.1.5 (Claude Code)`, `v1.2.3-beta.1`) and compared numerically; `unsupported_version` with upgrade guidance is emitted only when a minimum exists for that agent, the version parses, and it is strictly older (unparsable output and agents without a minimum stay `version_detected`, never a false "too old"). The same classification applies to PATH detection and to validated custom paths. Supports validated custom user-defined executable paths (`check_custom_ai_cli_path`: rejects missing paths, directories, non-executables, unknown ids). Frontend serves repeat panel opens from a 60 s stale-while-revalidate cache with explicit `force` refresh (`clearAiCliDetailsCache`); the panel labels the signal "Local config" (file present / no file / unknown) instead of "Auth".
- **Tests Added:** `test_detect_returns_all_catalogued_clis`, `test_version_success_does_not_imply_auth`, `test_probe_timeout_returns_quickly_for_missing_binary`, `test_missing_cli_reports_not_found_state`, `test_malformed_version_never_implies_auth`, `test_hanging_binary_probe_times_out_and_reaps`, `test_custom_path_rejects_directories_and_non_executables`, `test_parse_version_triple_handles_vendor_decoration`, `test_parse_version_triple_rejects_garbage_instead_of_guessing`, `test_classify_version_flags_only_strictly_older_parsable_versions`, `test_unsupported_version_diagnostic_gives_upgrade_guidance`, `test_min_supported_version_lookup_matches_table_entries_only`, `test_unsupported_version_state_serializes_and_needs_a_configured_minimum`, `test_config_presence_never_claims_valid_credentials`, `test_13_real_ai_cli_compatibility`, `src/__tests__/aiCliDiagnostics.test.ts` (cache invalidation, custom-id/path rejection, no-secret persistence).
- **Actual Test Result:** Passed.
- **Platform Coverage:** Cross-platform.
- **Remaining Limitation:** Auth check verifies local configuration file presence only; live API credentials are never tested over the network to prevent unintended costs. The version gate is wired but `MIN_SUPPORTED_VERSIONS` is intentionally empty: no vendor-verified minimum versions have been established for any catalogued agent, so `unsupported_version` is not emitted for any CLI today (adding a floor is a one-line table entry once a vendor-documented minimum exists).

### 1.7 Git Status Integration
- **Implementation Change:** Uses machine-readable git plumbing commands (`rev-parse`, `status --porcelain`) executed directly via process spawning (no shell, 8 s timeout per invocation, kill+reap on expiry, stdout piped + drained, stderr discarded to avoid >64 KiB deadlock stalls on large repos). Graceful error taxonomy (never panics): invalid/NUL/over-long paths, missing directories, inaccessible directories, non-directories, missing git binary ("Git is not installed or not on PATH"), and not-a-repo are reported distinctly. Correctly reports detached HEAD (`detached@<sha>`), unborn branches (0-commit repos report `repo_root` + branch), untracked / modified / deleted files, and dirty worktrees. Handles linked worktrees, nested repositories (innermost root wins), and unusual paths (spaces, unicode via `core.quotepath=off`). Implemented bounded per-directory caching (`getGitInfoCached`, 30s TTL, max 50 entries) with manual cache invalidation (`invalidateGitCache`); mutating service calls (`runGitAction`, `stage/unstage/discardGitFile`) invalidate up front and on completion so the badge can never go stale after an explicit change. Path traversal and symlink escapes from repository root are strictly validated and rejected.
- **Tests Added:** `src/__tests__/gitCache.test.ts`, `src/__tests__/gitIntegration.test.ts` (key normalization, TTL/explicit invalidation, mutating-action invalidation, missing-git/inaccessible taxonomy, spaces/unicode/nested keys), `test_branch_dirty_and_detached_head`, `test_unborn_branch_reports_repo_and_branch`, `test_worktree_nested_and_unusual_paths`, `test_large_repo_changes_stay_bounded`, `test_large_repo_status_is_bounded`, `test_invalid_dir_returns_error_not_panic`.
- **Actual Test Result:** Passed.
- **Platform Coverage:** Cross-platform.
- **Remaining Limitation:** Git status badge relies on local system `git` binary; if `git` is not installed on system PATH, the badge reports the missing-binary error without affecting terminal functionality.

## 2. Explicit Non-Goals & Security Guardrails

1. **No Remote Execution / SSH Daemon:** Kai connects strictly to local child shell processes on the host machine. It does not include built-in SSH connections, remote web sockets, or remote execution servers.
2. **Standard User Privileges:** Child shell processes run under standard OS user permissions. Kai does not bypass OS security or automatically elevate privileges; root (`sudo`) or Administrator elevation must be entered interactively by the user.
3. **No Credential Persistence or Telemetry:** Terminal input keystrokes, environment variables, scrollback logs, and credentials are never stored to disk, transmitted, or logged.
4. **Local Persistence Only:** Saved settings (`kai_user_settings`), active tab/pane layouts (`kai_workspaces_v1`), and recent projects (`kai_recent_projects`) are saved strictly in local browser storage (`localStorage`). Command history and terminal scrollback contents are never saved to disk.
5. **No Bundled AI Executables:** Third-party AI CLIs (Claude Code, Gemini CLI, Codex, etc.) are not bundled into Kai installers. If installed by the user, they can be executed inside regular terminal tabs.
6. **Non-Execution of Indexed Code:** Kai's project scanner never compiles, evaluates, or runs scripts discovered in indexed projects.

## 3. Implemented Capabilities Summary

- **Project Intelligence & MCP Server:** Terminal-first indexing (`kai code .`), status tracking (`kai status`), context querying (`kai query`), evaluation benchmarks (`kai bench`), optional LSP status inspection (`kai lsp status`), and read-only MCP server over stdio JSON-RPC.
- **Status Bar Intelligence Widget:** Native desktop status bar badge displaying project readiness, file count, and symbol count directly in Kai Terminal.
- **Split Panes:** Up to 8 split panes per tab (horizontal and vertical splits) with independent backend PTY processes per pane.
- **Custom Shortcuts:** Centralized shortcut manager with customizable keybindings, navigation shortcuts, and conflict detection.

- **Git Integration:** Displays active branch name and dirty status using system `git` with cached directory status and machine-readable output.
- **Local AI CLI Diagnostics:** Displays PATH detection, local version status, and non-modifying auth configuration status for AI coding tools without network calls or external data transfer.

## 5. Final Production Hardening (2026-10-14 audit)

### 5.1 `kai run` lifecycle guarantees and limits
- Agent exit outcome is preserved separately from graph sync: `0` on success, non-zero agent codes pass through, `124` on timeout, `130` on signal/cancel. Sync status is reported on its own line and never rewrites the agent outcome.
- Timeout/cancel sends SIGTERM, then SIGKILL after a 2 s grace period (`taskkill /PID /T /F` on Windows for the process tree). The promise resolves on child `close` (reaped).
- Shell stays disabled (`shell: false`) except for Windows `.cmd`/`.bat` targets (`process.platform === "win32"` gate), so user arguments cannot become shell metacharacters on POSIX.- Surviving-grandchild limit: a detached grandchild that outlives its parent cannot be reaped from Node. Timeout/signal outcomes therefore force the broader (`full`) refresh path and are reported as point-in-time freshness; if the tree keeps writing, rerun `kai graph status` / `kai graph update`. Sync never claims a surviving writer is fully accounted for.

### 5.2 Change detection and freshness truthfulness
- Freshness covers modified/deleted tracked files (mtime/size plus ctime, which user-space tools cannot restore), case-only renames (realpath basename check), and untracked new files (bounded readdir-only walk with the same exclusion rules, so `node_modules`/`.git`/ignores/sensitive/binary/oversized files never mark stale). Racily-clean files (mtime/ctime within `RACY_TIMESTAMP_WINDOW_MS` = 5 s of the snapshot, at most 200 per check) are re-hashed against the stored sha256, so a same-size edit with a preserved or coarse timestamp is still caught. Residual: only an edit that preserves size, mtime AND ctime on a file hashed more than 5 s after its last modification can evade detection until the next full rebuild.
- After every sync publish, the just-written graph is re-checked; disk movement during the non-atomic build keeps the graph marked `stale` with a follow-up-refresh warning instead of falsely reporting `fresh`.
- Dedup shares one rebuild only for the same project AND the same normalized change set/flags; different projects, different file lists, or different `uncertain`/`forceFull` run separately (serialized by the index file lock plus a generation guard so an older candidate can never overwrite a newer graph). File locks always release via `finally`.

### 5.3 Crash consistency (handled recovery, same format)
- Each file write is atomic (temp file + rename; Windows retry on AV transient locks). `saveProjectIndex` performs two sequential renames (`index.json` then `meta.json`), but every save stamps one shared `snapshotId` (UUID) on `meta.json`, the embedded index `meta`, and the top-level index — so a crash between the renames leaves mismatched ids that `checkPersistenceConsistency` detects (id / canonical-path / incarnation / schema / status / snapshot / timestamp-structure checks) and that every freshness-reporting path validates first (`getValidatedFreshness`, the `ensureFreshIndex` gate, the sync skip-path upgrade to a full rebuild, `kai_project_info`, `planCodeTask`, CLI `status`): a torn snapshot is never reported as `fresh`. Detection is fail-closed (timestamp skew can only force an extra safe rebuild, never a false `fresh`); recovery reuses the existing bounded single-attempt rebuild (which also normalizes the schema so it converges), and a failed rebuild preserves the last-known-good graph and reports `stale`, never looping. Abandoned `*.tmp` files older than 60 s are cleaned on registration and after saves; a concurrent writer's fresh temp files are left alone. `generatedAt` and embedded `lastIndexedAt` share one timestamp. Startup never crashes on partial state (`registerProject` resets stuck `indexing`; corrupt JSON is recreated). No new storage format was introduced (snapshot id is additive and optional; legacy snapshots stay loadable via the timestamp-skew check). Residual user-facing cost of a torn snapshot is one extra safe rebuild plus a `stale` report until it completes — a handled recovery condition, not a correctness defect.

### 5.4 MCP freshness contract
- Graph-dependent reads (`kai_search_code`, `kai_find_symbol`, `kai_get_dependencies`, `kai_get_context`, `kai_read_range`) run one bounded auto-refresh when not fresh and report `freshness` + `refreshOutcome` (+ truthful `refreshWarning` on failure); `kai_project_info` reports `freshness` without triggering work; `kai_get_context` prepends a freshness warning line when the result is a stale fallback (tool names/required args unchanged).
- A pure-MCP client that never spawns the agent MUST follow writes with either a graph-dependent read (which gates freshness automatically) or an explicit `kai_sync_graph` / `kai_refresh_index` call, or the server must be started with the opt-in watcher (`kai mcp --watch` or `KAI_MCP_WATCH=1`), which debounces filesystem events and runs the same bounded `ensureFreshIndex` pass in the background. The watcher is off by default (no background activity unless requested), skips excluded/dot directories, and degrades to read-time gating if the platform cannot watch the tree.

### 5.5 Platform verification in this audit
- Native execution: the CI matrix (`.github/workflows/ci.yml`) runs the security, CLI-smoke, lifecycle, Rust, and PTY checks natively on ubuntu-22.04, windows-latest, and macos-14, and all three jobs passed for commit `e017786` (2026-10-15). This is automated CI verification only; no manual interactive session on Windows/macOS is claimed, and WSL remains manual-only (no hosted runner).

### 5.6 Release hardening: incarnation identity, process lifecycle, snapshot consistency
- **Project incarnation checks:** every registration mints (or preserves, on idempotent re-lookup) a random `incarnation` token persisted in `meta.json`. Tasks capture the token at start (`runCodeTaskWithAutoSync`) and carry it through planning, execution, synchronization, and publication; `verifyProjectIdentity` compares the captured token against the registry before any index refresh and immediately before publishing. Deleting a project and re-registering the same path mints a new incarnation, so a stale task is rejected with an `incarnation changed` message instead of publishing into the new project. Caller-provided tokens are never trusted without a registry comparison; legacy metadata without a token is upgraded on re-registration, and a token-less capture is refused against a token-bearing registration. Idempotent re-registration of a still-live project (e.g. concurrent MCP reads, which call `registerProject` on every tool call) preserves the token so live tasks are not spuriously invalidated. Process restart makes old tasks unresumable by design (captures live in memory), so the token only needs registry persistence, not cross-process handoff.
- **Process-tree termination guarantees and limits:** `runExternalAgentCommand` spawns POSIX children as process-group leaders (`detached: true`) and terminates the whole group (`kill(-pid, SIGTERM)`, escalated to `SIGKILL` after 2 s); on Windows it uses `taskkill /PID /T /F` plus SIGTERM/SIGKILL escalation. Abort, timeout, child error, spawn failure, and normal exit are distinct outcomes (`outcome: exited | timeout | aborted | spawn-error`, with `aborted` / `spawnFailed` / `spawnError` fields); an already-aborted signal resolves without spawning; completion settles exactly once with all timers and listeners cleaned up on every path. Shell stays disabled except Windows `.cmd`/`.bat` (`needsShellForCommand`). NOT guaranteed: a descendant that detaches into its own session/group (double-fork, `setsid`, Windows detached processes) escapes tree termination and cannot be reaped from Node — such outcomes set `descendantsMaySurvive`, force the broader (`full`) refresh path with `uncertain` scope, and are reported as point-in-time freshness with a follow-up-refresh warning. No polling loop or background service was added.
- **Uncertain completion and synchronization:** `runCodeTaskWithAutoSync` forces `uncertain: true` for failed/cancelled tasks (in addition to caller-reported uncertainty), and `kai run` already forces it on timeout/signal/abort. Sync failure never rewrites the agent's exit outcome (exit codes `0` / pass-through / `124` timeout / `130` signal-cancel preserved) and never erases source changes. The sync report states the scope, result, freshness, and warnings; termination attempt vs. confirmation is surfaced via `treeKillAttempted` / `descendantsMaySurvive` on the command result and via CLI notes.
- **Persistence consistency and recovery:** every save stamps one shared `snapshotId` (UUID) on `meta.json`, the embedded index `meta`, and the top-level index. `checkPersistenceConsistency` validates readability, project id, canonical-path identity, incarnation pairing (when both copies carry one), schema compatibility (unsupported versions flagged), status agreement, snapshot agreement, timestamp sanity plus a fail-closed skew cross-check (skew can only force an extra safe rebuild, never a false `fresh`), and required index structure. Missing files mean nothing to compare (consistent); truncated/malformed JSON, mismatches, and invalid structure are inconsistent. Legacy snapshots without ids rely on the timestamp-skew check and stay loadable. Every freshness-reporting path validates first (`getValidatedFreshness`, the `ensureFreshIndex` gate, the sync skip-path upgrade to a full rebuild on mismatch, `kai_project_info` reporting, `planCodeTask` gating, CLI `status` notes) — a torn snapshot is never reported as `fresh`. Recovery reuses the existing bounded single-attempt rebuild (a rebuild also normalizes the schema so it converges); a failed rebuild preserves the last-known-good graph and reports stale, never looping. Abandoned `*.tmp` files older than 60 s are cleaned on registration and after saves; fresh temp files from a concurrent writer are left alone. No new database or index format was introduced.
- **Native CI coverage:** the matrix (ubuntu-22.04 / windows-latest / macos-14) runs typecheck, the full suite, security regression, CLI smoke, and a `Lifecycle & persistence targeted tests` step (`releaseHardening`, `finalHardening`, `autoSyncLifecycle`, `codeModeWorkflow`, `codeMode`) natively per OS; platform jobs are mandatory (no optional green). All three jobs passed for commit `e017786` (2026-10-15). Case-only rename behavior is filesystem-dependent: covered with a truthful test that asserts convergence without claiming case-insensitive detection on case-sensitive volumes.
- **Pure-MCP lifecycle boundary:** a pure-MCP client that never spawns the agent must still follow writes with a graph-dependent read (auto-gated) or an explicit `kai_sync_graph` / `kai_refresh_index` call unless the opt-in `--watch` / `KAI_MCP_WATCH=1` watcher is enabled (off by default; see 5.4). `kai run` remains the only path with automatic completion synchronization without the watcher.

## 6. Retrieval, response bounds and token accounting (2026-10-28)

### 6.1 Index freshness and scan completeness
- Files the indexer inspected and rejected on content (secret-looking, binary-looking) are remembered; a failed read ("unreadable") is remembered for only a minute, since locks are often transient, in an optional `skipped` map (stat metadata only: no content, no hash) so they are no longer rediscovered as "new" on every read, which used to force a full refresh and an `index.json` rewrite per request. A record is honoured only while size, mtime and ctime are unchanged; any edit makes the file eligible again, and a forced rebuild forgets all records.
- `scan` on the index records whether the last directory walk was complete (file-count cap, depth cap, unreadable directories) and counts skips by reason. Graph reads, `kai_project_info` and `kai_refresh_index` surface it. **When the 10,000-file cap is hit, files beyond it are not indexed and *new-file detection is switched off* for that snapshot** (otherwise the cap would refresh forever); edits and deletions of indexed files are still detected. Raising the cap is not supported.
- Old indexes load unchanged. A snapshot without `extractorVersion` is treated as stale once, re-extracted on the next graph read, and then settles.

### 6.2 Symbol and import extraction is text-based, not a parser
- `src/core/symbolExtractor.ts` blanks comments, strings, template and regex literals, then recognises declarations at statement starts while tracking brace depth (indentation for Python). It is **not an AST** and makes no AST-level claims. Wrapped signatures, class/impl/trait members, ranges (`line` to `endLine`), `export { }` lists, multi-line imports, Go import/const/var blocks and Rust `use` groups are handled and covered by fixtures.
- Known limits: regex-vs-division and JSX text can still be mis-scanned (an unterminated quote is treated as plain text, bounding the damage to its line); macros and generated code are not expanded; lines over 2,048 characters (minified code) are ignored; private class properties (`private`, `#x`) and constructor parameter properties (`constructor(private x)`) are not indexed (constructors and the other properties are, as symbols named `constructor` / the property name inside their class); Rust trait-impl methods are marked exported only when the type is an unrestricted `pub` item of the same file and any trait of that file is `pub` (a type or trait declared in another file leaves them unexported); Python scoping is indentation-based and decorators are ignored. Only unrestricted `pub` counts as exported in Rust.
- Import resolution (`importResolver.ts`) covers relative TypeScript/JavaScript and Python imports; tsconfig/jsconfig `paths`/`baseUrl` aliases from the nearest config (through `extends`, including arrays and packages inside the project's `node_modules`, and through `references` of a solution-style `tsconfig.json`); Python absolute imports of project modules under the project root, `src/` and the source directories declared in `pyproject.toml` / `setup.cfg` (`pythonRoots.ts`), including namespace packages across roots; re-exports through barrels, `__init__.py` and Rust `pub use` (named, star, default and namespace imports included); Rust `crate::` / `self::` / `super::` paths, `mod foo;` declarations and other crates of the same Cargo workspace; and Go import paths under a `go.mod` module (or local `replace`) of the project (`rustGoModules.ts`). Only import relationships exist; there is no call graph. Each dependency reports what it could not do (`resolution`: `resolved`, `unresolved`, `non-relative`, `unsupported`). Not resolved:
  - package names, and Rust crates or Go modules outside the project;
  - tsconfig `include`/`exclude` for anything but picking which *referenced* config applies (a file's own config is the nearest `tsconfig.json`/`jsconfig.json`), configs not named `tsconfig.json`/`jsconfig.json` unless reached through `extends` or `references`, a referenced config's inherited (not own) `files`/`include`/`exclude`, and more than 64 configs per project;
  - Python package dirs mapped to a different name (`package-dir = {"pkg" = "lib/other"}`), `setup.py`, and a project module that shares its name with a standard-library module when the importer is in another directory (it stays the standard library);
  - side-effect imports (`import './barrel'`) through a barrel, and re-export chains deeper than 3 levels or more than 8 extra files per import. A star export is followed only into files that export the imported name, and never for a default import;
  - Rust `#[path = "..."]` modules, `mod foo;` inside an inline `mod { }`, 2015-style relative `use` paths and macro-declared modules; Go vendored and module-cache packages, `go.work`, build tags, and any package past its 8 first non-test files (a Go import is recorded against the package's files in name order, not per symbol);
  - a Rust crate root is the nearest `lib.rs`/`main.rs` above the file, so a single-file binary under `src/bin/` is attributed to the library root.
  A specifier that matches a configured alias, a Rust `crate`/`self`/`super` path, a workspace crate, or a Go module of the project but has no indexed target is `unresolved`, not `non-relative`. Python resolution is by file name only.

### 6.3 MCP response bounds
- Every tool result, and every error, is bounded in UTF-8 bytes of the whole JSON-RPC line (envelope, wrapper and the escaping caused by embedding JSON in a text field included). The ceiling is 64 KiB by default; `KAI_MCP_MAX_RESPONSE_BYTES` sets it between 8 KiB and 1 MiB. Collections paginate with `limit`/`offset` and report `total`, `returned`, `hasMore`, `nextOffset`; when the byte ceiling cuts a page short the same fields describe where to resume, `truncated: true` is set, and required fields are never dropped. JSON-RPC ids over 256 bytes are rejected. The ceiling is measured on the JSON line itself; the stdio server appends one `\n`, so the bytes on the wire are at most the ceiling plus one.
- `kai_get_context` is capped by the ceiling as well as by `tokenBudget`, so a very large budget may yield less than requested.
- Change lists are no longer returned in full: `kai_project_info` and `kai_refresh_index` return counts (`changes: {added, modified, renamed, deleted, skipped}`) and, with `includeChanges: true`, a paginated `changeDetails`. Redundant fields were removed from items (`sourceFile` per dependency, `location.filePath` per symbol).

### 6.4 Metadata-first retrieval and `kai_read_range`
- `kai_search_code` is metadata-first: by default it returns paths, ranked reasons, matching symbols with line ranges, a content hash and a size estimate, and never touches the filesystem; `kai_read_range` then reads exactly one symbol or line range. **Behaviour change:** snippets used to be on by default; they are now opt-in with `includeSource: true`, which returns the previous snippet-bearing response. Callers that relied on the old default must pass it.
- `kai_read_range` reuses the retrieval reader (secret-path and secret-content screening, root confinement with realpath, symlink-escape rejection, binary and size checks) and only reads files that are in the index, so a file skipped for secret content is never readable. An `expectedHash` mismatch returns `status: "stale"`; symbol ranges from an index older than the file return `stale` too. Ambiguous symbols return a bounded candidate list. Requests larger than `maxLines` (default 200, hard cap 400) are rejected.

### 6.5 Token figures are estimates
- Kai bundles no tokenizer and does not call a model. Counts come from a character-class heuristic that has **not** been calibrated against any real tokenizer (none is installed here); the old "cl100k" labels were wrong and are gone. Telemetry (`metrics.jsonl`) records the heuristic size of the response actually returned, flagged `tokensAreEstimate`, plus byte sizes, counts and timings. It is not model-reported usage, and it records no source, prompts or paths.

### 6.6 Caching and repeated work
- Read paths reuse a frozen, bounded (3 projects, ~96 MiB estimated) in-process copy of the parsed index, validated on every use against `index.json`'s stat signature. Derived tables (symbol-name table, reverse imports) are computed once per index object. `meta.json` is no longer rewritten when nothing changed. Source text is never cached.
- The index lock is still held for the whole scan-and-write: that is what keeps the snapshot consistent, so it was not narrowed.

### 6.7 Task-aware budgets and early stopping in `kai_get_context`
- With no `tokenBudget`, the budget starts from the classified task type (explain/documentation 1,700; review/test/debug 3,000; implement, architecture, refactor and unclassified 4,000, the old flat default; no category is above it). `KAI_CONTEXT_BUDGETS` (JSON, category to tokens, clamped to 200-20,000) overrides them. **These are experimental starting points, not tuned optima.** Larger defaults for implement/architecture/refactor (4,500 to 6,500) were tried first and removed: on the 10-task benchmark they raised refactor-task responses by up to ~50% (p95 bytes and estimated tokens got worse than baseline) while the expected file was already retrieved at 4,000. An explicit `tokenBudget` is honoured as given and keeps the exhaustive behaviour (no early stop).
- Under a task-aware default, files scoring below a quarter of the best match are not padded in (the best two are always kept). They are reported as `low_relevance` omissions, never dropped silently. Rules and skills may use at most 40% of what remains after the fixed framing, so they cannot crowd out the source.
- The budget covers the context package only. The fixed framing alone is about 800 estimated tokens, so budgets below roughly 1,500 leave little for source; the package is not the model's full input (system prompt, conversation, tool results and the reply are separate and not measured here). A lone remaining source is halved on a line boundary (the reported line range follows) before being dropped, and the package says so.
- The classifier is keyword- and pattern-based: a phrasing it has no pattern for classifies as `unknown` and gets the 4,000 default. Renames are recognised as `rename X to/into/as Y` (optionally with a kind word), `change the name of X to Y`, `replace X with Y`, `migrate/switch/swap X to/for Y` and `move X into its own file`; other wordings ("X should be called Y") are not.
- Known retrieval gap: files the indexer rejects as `sensitive_content` are never retrievable. `src/core/indexer.ts` is one (it contains secret-detection patterns, so the fail-closed filter treats it as a credential file). The filter was deliberately not loosened; a project that wants such a file searchable needs a reviewed change to the filter.

### 6.8 Anchored ranking and bounded neighbour expansion (2026-10-28)
- **Anchor.** An identifier typed in full (camelCase or snake_case, such as `cancelOrder`) that names an indexed symbol anchors the query. A plain word that equals a symbol name (`order` for `interface Order`) does not: it cannot be told from prose. The words obtained by splitting an anchoring identifier keep a quarter of their path and import credit (`ANCHORED_PART_WEIGHT`); a word the user also typed on its own keeps full weight.
- **Anchored floor.** With a task-aware default budget and an anchor, the relevance floor is 0.5 of the best score instead of 0.25 (`ANCHORED_MIN_SCORE_RATIO`). Swept at 0.25, 0.4, 0.5, 0.6 and 0.75 on the task suite and the real repo: 0.6 already lost a support file in the suite, 0.5 is the highest value that lost none. These constants are tuned on one synthetic suite and this repository; they are starting points, not optima.
- **Expansion** (`expandNeighbors`, `retrieval.ts`). Only with a default budget and an anchor: callers (files that import the anchor's file and really mention the symbol; usage excerpts of at most 30 lines; **refactor only**) and tests that import its file (first 40 lines; refactor, debug, implement, test). One hop through the import graph, no second anchor. Stops at 8 callers, 2 tests, 40 importers examined, or the remaining token budget. Everything not delivered is reported as one `N more importer(s) ... not examined` omission; a neighbour that did not fit is named. Neighbours are read through the same secret-screening and root-confinement reader as ranked files, are labelled `caller of X (file)` or `test importing file` instead of a score, and are never added when the caller passes an explicit `tokenBudget`.
- **Limits.** Import edges only: no call graph, so a caller that reaches the symbol through a dynamic reference or a side-effect import of a barrel is missed (default and namespace imports of a barrel are followed). Tests are found only if they import the anchor's file. Test and caller neighbours are excerpted from the first use of the symbol after the file's import block (the top of the file when the test only imports it).
- **File anchor** (`implement` tasks, default budget only). With no named symbol, a file that clearly dominates the ranking (`FILE_ANCHOR_MIN_SCORE` = 20, `FILE_ANCHOR_DOMINANCE` = 1.5 times the runner-up) adds the tests that import it and up to `MAX_EXPANDED_IMPORTS` = 3 definitions it imports (30 lines each). No callers (there is no symbol to look for), and a diffuse request such as "add an endpoint" with no single obvious file still gets no neighbours. The two constants are tuned on one synthetic fixture and this repository, not optima.
- **Cost.** Where neighbours are added the response grows: on the real repository 3 of 10 default-budget tasks grew 7 to 17% against the previous build (`registerProject` refactor +15%, "fix ... assembleContext" +17%, "add an option to toolReadRange" +7%), and p95 response bytes rose from 7,967 to 9,036. These figures predate the usage-based test/caller excerpts and the file anchor and were not re-measured across all ten tasks (one task re-run: 7,695 to 7,266 bytes). Freed budget can also be refilled by generic skill text (the bug-fix task gained ~5% that way); the benefit of those skills is not measured and the policy was left unchanged.
- **Not measured.** No model runs in the benchmark. "Success" is a retrieval proxy (every file the change must edit had its source delivered), not task completion; coding-task completion rate, regressions in generated code and real model token usage are unverified. Token figures are bytes/4, labelled estimates.
