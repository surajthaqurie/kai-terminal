# Kai Terminal — Themes

Ten themes ship: **Kai Dark** (default), Catppuccin Mocha, Tokyo Night, Nord, One Dark, Dracula,
Solarized Dark, Gruvbox Dark, Rosé Pine and **Kai Light**.

## Single source of truth

Every theme colour is written once, in [`src/theme/registry.ts`](../src/theme/registry.ts):

```ts
interface ThemeDefinition {
  id: string;                       // "kai-dark" — also the persisted setting value
  name: string;                     // Settings label
  colorScheme: "dark" | "light";    // native form controls / scrollbars
  chevron: string;                  // <select> chevron stroke colour
  orange: string;                   // the one tab colour ANSI has no slot for
  chrome: Record<ChromeToken, string>;  // 30 window tokens → --bg-*, --text-*, --accent-*, …
  terminal: TerminalPalette;        // xterm ITheme: bg, fg, cursor, selection, 16 ANSI colours
}
```

Everything else is **derived**, never hand-written:

| Artefact | How it is produced |
|---|---|
| `src/styles/themes/<id>.css`, `themes/index.css` | Generated by `npm run themes:generate` |
| `index.html` first-paint `<style>` + boot map | Generated (between `theme:first-paint` markers) |
| xterm palette, canvas colour | `getTheme(id).terminal`, `canvasColor()` at runtime |
| Settings swatch | `themePreview()` (bg / fg / accent from the theme itself) |
| Tab colours | `tabColors()` → `--tab-color-{blue,green,…}` in the generated CSS |
| Search highlights | `searchDecorations()` (#rrggbb, as xterm's search addon requires) |
| Applying a theme | `applyThemeToDocument()` in `src/theme/applyTheme.ts` (one function) |

`themeRegistry.test.ts` regenerates every artefact in memory and fails if a committed file differs, if a
theme colour token is declared anywhere outside the generated files, or if a swatch/palette/canvas
disagrees with the registry.

### First paint

`index.html` paints the saved theme's canvas colour from an inline `<style>` and a tiny boot script
before any JavaScript bundle or stylesheet loads, and sets `color-scheme` (light/dark) at the same time.
No runtime CSS generation is involved. The native window still starts in the Kai Dark canvas colour
(`tauri.conf.json`), so a Kai Light user can see one dark native frame before the page paints (a known
open item).

## Adding a theme

1. Add a `ThemeDefinition` to `THEMES` in `src/theme/registry.ts` (all 30 chrome tokens and the full
   terminal palette are required by the type). Set `terminal.background` equal to `chrome["bg-surface"]`.
2. `npm run themes:generate`.
3. `npx vitest run src/__tests__/themeContrast.test.ts src/__tests__/themeRegistry.test.ts` and fix any
   contrast failure by adjusting the colours (never the thresholds).
4. Add the id to `EXPECTED_THEMES` in `themeContrast.test.ts`. If the theme should migrate from an old id,
   add it to `LEGACY_THEME_IDS` in `settingsService.ts`.

No other file needs to change: the Settings grid, type `ThemeName`, startup paint and `isLightTheme()` all
follow the registry.

## Contrast requirements (identical for all ten themes)

Enforced by `themeContrast.test.ts`, `uiRefinement.test.ts`, `paneDividerContrast.test.ts`:

| Pair | Minimum |
|---|---|
| primary / secondary / tertiary text on surface and canvas | 4.5:1 |
| primary / secondary / tertiary text and danger on the **elevated** surface (menus, palette, cards) | 4.5:1 |
| accent and success / warning / danger / purple text on surface | 4.5:1 |
| badge text on its tint, over surface **and** elevated | 4.5:1 |
| primary text on the selection tint (`accent-subtle`) | 4.5:1 |
| `text-inverse` on accent (primary button) and on danger (danger button hover) | 4.5:1 |
| secondary vs tertiary text (hierarchy must be visible) | 1.25:1 and correctly ordered |
| secondary / tertiary text on tab bar and status bar | 5.4 / 5.2:1 |
| split divider over the terminal background | 1.6:1 |
| terminal foreground on terminal background | 4.5:1; on the selection tint 3:1 |

## Theme changes made in this pass

- **Kai Light** added: a full light theme (sunken `#eef0f3` < surface `#fafbfc` < elevated `#ffffff`), Kai
  cyan darkened to cyan-700 `#0e7490` for 4.5:1 on white, light ANSI palette.
- **Kai Dark** terminal selection: VS Code blue `#264f78` → cyan tint `#22d3ee40`.
- **M3 hierarchy retune** (smallest change meeting the targets): One Dark text `#abb2bf/#949baa/#9198a5`
  → `#c2c7d0/#b1b7c1/#9ca2ae`; Solarized `#93a1a1/#869798/#82969b` → `#b5bfbf/#a3b0b1/#8b9da2`;
  Gruvbox tertiary `#a79d82` → `#aba187`.
- **Badge / elevated contrast**: badge tints lowered toward 8% where needed and a few semantic foregrounds
  lightened by a few percent (Nord, One Dark, Dracula, Solarized, Gruvbox, Tokyo Night, Rosé Pine, Kai
  Light). Accent colours and the selection tint were deliberately **not** changed.
- **Solarized swatch drift** fixed by construction (swatches are now derived).
- The per-theme `--bg-tab-bar/--bg-statusbar/--bg-tab-*` values that `.app-layout` silently overrode
  are gone; those are now aliases in `tokens/semantic.css`. `--bg-toolbar` (unused) removed.
