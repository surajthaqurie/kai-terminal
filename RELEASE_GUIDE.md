# Production Release & Deployment Guide

This guide details code signing configuration, installer generation, GitHub Release deployment, and pre-release verification.

---

## 1. Code Signing & Notarization

To avoid operating system security warnings (Windows SmartScreen, macOS Gatekeeper), release binaries should be signed prior to distribution.

> [!IMPORTANT]
> **Secrets Security:** All certificates, passwords, and private keys must be stored strictly in GitHub Repository Secrets. No secret keys or certificates should ever be committed to the repository.

### 1.1 Windows Code Signing (Authenticode)
- **Certificate Format:** Base64-encoded `.pfx` certificate.
- **GitHub Action Secrets:**
  - `WINDOWS_CERTIFICATE`: Base64 string of `.pfx` file.
  - `WINDOWS_CERTIFICATE_PASSWORD`: Password for `.pfx` file.

### 1.2 macOS Code Signing & Notarization
- **Certificate Format:** Apple Developer ID Application (`.p12`).
- **GitHub Action Secrets:**
  - `APPLE_CERTIFICATE`: Base64 string of `.p12` developer certificate.
  - `APPLE_CERTIFICATE_PASSWORD`: Password for `.p12` certificate.
  - `APPLE_ID`: Apple Developer account email.
  - `APPLE_PASSWORD`: App-specific password generated on appleid.apple.com.
  - `APPLE_TEAM_ID`: 10-character Apple Developer Team ID.

### 1.3 Tauri Updater Signing (Optional)
- **GitHub Action Secrets:**
  - `TAURI_SIGNING_PRIVATE_KEY`: Private key generated by `tauri signer generate`.
  - `TAURI_KEY_PASSWORD`: Key passphrase.

## 2. Installer Formats & Output Locations

Installer packages are generated by `npm run tauri build` in `src-tauri/target/release/bundle/`:

| Operating System | Installer Target | Extension | Output Location |
| :--- | :--- | :--- | :--- |
| **Linux** | DEB Package & AppImage | `.deb`, `.AppImage` | `src-tauri/target/release/bundle/deb/`, `bundle/appimage/` |
| **Windows** | NSIS Setup & MSI | `.exe`, `.msi` | `src-tauri/target/release/bundle/nsis/`, `bundle/msi/` |
| **macOS** | DMG Disk Image & App Bundle | `.dmg`, `.app` | `src-tauri/target/release/bundle/dmg/`, `bundle/macos/` |

---

## 3. Update Verification & Status

In-app release checking (`Settings > Check for Updates`) queries the public GitHub Releases API (`https://api.github.com/repos/surajthaqurie/kai-terminal/releases/latest`) and allows users to open the release download page directly in their default system browser. Background silent binary replacement is disabled by default to keep installations explicit and user-directed.

---

## 4. Production Release Checklist

Before releasing a new version tag:

- [ ] **Run Quality Checks:** Pass all frontend checks (`npm run check`).
- [ ] **Run Backend Unit Tests:** Pass all Rust tests (`cargo test --no-default-features --manifest-path src-tauri/Cargo.toml --lib`).
- [ ] **Run PTY Integration Tests:** Pass integration scenarios (`cargo test --no-default-features --manifest-path src-tauri/Cargo.toml --test pty_integration_tests`).
- [ ] **Update Version:** Update version numbers in `package.json`, `src-tauri/Cargo.toml`, and `src-tauri/tauri.conf.json`.
- [ ] **Tag & Push:** Create git tag (`v0.1.4`) and push to trigger automated release publishing on GitHub:
  ```bash
  git tag v0.1.4
  git push origin v0.1.4
  ```
